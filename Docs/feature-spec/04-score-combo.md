# 4. 점수 & 콤보 (Score & Combo)

> 실제 구현은 아래 단순한 상수 기반 공식이다 — 기획 초기에 검토했던 매치 개수별 배율(3/4/5+ 각각
> 다른 배율)은 시간 관계상 적용하지 않았고, `GameConfig` 같은 별도 SO도 두지 않았다(하드코딩 금지
> 원칙은 `GridController`의 명명된 상수로 대신 지킨다).

## 점수 공식 (실제 구현 — `GridController.PointsPerTile`, `ResolveOneStep`)
- `이번 스텝 점수 = 이번 스텝에서 제거된 타일 수 × PointsPerTile(10) × (캐스케이드 스텝 번호 + 1)`
  - 스텝 번호는 0부터 시작(교환이 만든 첫 매치 = 0번째, 그 다음 캐스케이드 = 1번째 ...) — 뒤로
    갈수록 배율이 커져 깊은 캐스케이드일수록 점수가 커진다
- 매치 타일 개수(3/4/5+)에 따른 별도 배율은 없다 — 특수 타일 생성 조건(§`12-special-tiles.md`)에만
  영향을 줄 뿐, 점수 자체는 순수하게 "이번 스텝에서 몇 개 지웠는가"로만 결정된다
- `IngredientData`에는 점수 관련 필드가 없다(§`02-board-tile.md`) — 전 타일 공통 점수

## 콤보 정의
- **1회 교환(또는 특수 타일 활성화)으로 시작된 캐스케이드 안에서 발생한 매치 스텝 수**
  (`GridController.ResolveCascadeAndFinish`의 `steps.Count`) = 콤보 카운트
  - 예: 교환 → 매치(스텝0) → 캐스케이드로 추가 매치(스텝1) → 추가 매치(스텝2) = 콤보 3
- 콤보(스텝 수 2 이상)에는 위 점수 공식과 별개로 **콤보 보너스**가 추가로 붙는다(2026-08-05,
  "콤보 추가 점수도 적용해주세요" 요청) — `ComboBonus = ComboBonusPerStep(20) × (steps.Count - 1)`,
  캐스케이드가 완전히 끝나 최종 스텝 수가 확정된 시점에 한 번에 더해진다(`GridController.
  ResolveCascadeAndFinish` 끝부분 참고). 스텝별 기본 점수는 각 스텝이 재생되기 전에 이미 즉시
  `Score`에 더해지므로(캐스케이드가 몇 스텝짜리인지 그 시점엔 아직 모름), 콤보 보너스만 별도로
  캐스케이드 종료 시점에 붙는다. 위 "스텝 번호 + 1" 항도 여전히 그대로 유지되어, 콤보가 깊어질수록
  두 항 모두 점수를 키운다.
- 콤보는 캐스케이드 종료 시 확정, 다음 교환에서 다시 0부터 계산(스텝 카운트가 자연히 리셋됨)

## 최고 콤보 추적
- `GridController.MaxCombo` 프로퍼티가 라운드(캠페인 전체, 스테이지 전환에도 유지) 중 발생한 콤보
  카운트의 **최댓값**을 직접 보유한다 — 별도 이벤트(`OnComboTriggered` 등)는 없고,
  `Match3Controller`가 게임 오버 시점에 이 프로퍼티를 직접 읽어 `PuzzleHud.ShowGameOver(score,
  maxCombo)`로 넘긴다
- 결과 화면(§`06-ui.md`)에 최종 점수 + 최고 콤보로 표시
